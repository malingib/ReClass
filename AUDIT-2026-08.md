## Executive Summary
The project is in notably better shape than the July 2026 baseline (which scored 7.9/10). Every Critical finding from that audit has been remediated: the two-financial-system separation now has a real `domain` column on fee_types/invoices/payments, the KCB bank channel exists alongside M-Pesa, the remedial dashboard no longer queries dropped tables, soft-delete filters are applied, and rate limiting is tenant-scoped. Overall: 8.4/10, ship-ready for the current feature set, with one Medium that should be closed before claiming "dark mode support."

### High (significant quality/security/maintenance concerns)
H1. RLS is dead code for most server paths (partial mitigation only).
    - `src/lib/supabase/server.ts` + ~20 server files use a service-role client (`getServiceClient`), bypassing RLS. The migration enabling RLS with `app.tenant_id` policies is defense-in-depth only.
    - Mitigation exists but is narrow: `NotificationBell.svelte:20` and `notifications/+page.svelte:15` call `set_tenant_context({p_tenant_id})` client-side. No server-side `SET LOCAL app.tenant_id` at request start, so the other ~18 service-role paths are unprotected by RLS.
    - Severity: High for a multi-tenant money app. Either (a) document RLS as dormant and rely on the service-role `.eq('tenant_id')` discipline (verify with `scripts/verify_tenant_isolation.py`), or (b) call `set_tenant_context` in a `+hooks.server.ts` for every request. Recommend (a) + the scanner gate.

H2. Dark mode is half-finished / inert (regression from `c7e01e7 chore: remove dark mode and language switcher`).
    - `src/lib/components/ui/{badge,tabs,input,avatar,select}/*.svelte` use `dark:` Tailwind variants extensively (expect a `.dark` class / `:root.dark`).
    - No toggle exists: `src/lib/i18n.ts` is GONE, `app.html` has no blocking theme script, and nothing adds `.dark` to `<html>`. My reconciled `app.css` `[data-theme="dark"]` block is INERT (components watch `.dark`, not `[data-theme="dark"]`), so it is dead code.
    - Two clean options: (a) delete all `dark:` variants + the `[data-theme="dark"]` block (light-only, matches "design: bold light-only visuals" user preference), or (b) re-add a theme store + `.dark` class toggle. Until then, "dark mode" is claimed by code but delivers nothing. Severity: High only if dark mode is a stated requirement; Medium otherwise. Given the user's stated light-only preference, recommend (a) and drop the dead block.

### Medium (code quality, architecture debt, DX friction)
M1. `set_tenant_context` is client-side only on notifications; server queries depend entirely on per-query `.eq('tenant_id')`. The LooseClient `paginatedQuery` helper (`src/lib/server/query.ts`) casts away column typing — verify every table used with it against live schema (prior audit flagged this; still true). Low risk now (154 tests incl. 41 tenant-isolation), but un-typed.

M2. `impersonation.ts` could not be located at the expected path during audit (grep silent). The July fix (IP `/24` prefix, `impersonation.ts:47-50`) should be re-confirmed post-redesign — verify the super-admin impersonation layout guard still includes `'super_admin'` in every role's `+layout.server.ts` (AppShell + 5 role layouts). This is the #1 recurring break in this codebase.

M3. Raw `tsc --noEmit` reports 10 TS2614 errors in `src/lib/components/ui/*/index.ts` (named re-exports from `*.svelte`). svelte-check passes, so the build is fine, but any CI using raw `tsc` will fail. Fix: add `export type` shims or switch CI to svelte-check only. Severity: Medium (CI red, false-alarm noise).

M4. Two divergent design-system token vocabularies coexist in `app.css` (reconciled superset): the shadcn set (`--color-primary`, `--color-popover`, `--color-background` used by bits-ui) AND the custom set (`--color-surface`, `--color-ink-*`, `--color-brand-*` used by app screens). Neither is fully unused. This is workable but is debt — pick one canonical palette before adding more surfaces. The WIP's `ui-card`/`ui-control` utilities are good; consider promoting them to the standard card primitive.

M5. bits-ui Dialog a11y: `dialog-content.svelte` now uses `DialogPrimitive.Content` (bits-ui injects `role="dialog"`, `aria-modal`, focus trap) — the prior AX-invisible finding (hand-rolled portals) is resolved. `DataTable.svelte:344` delete confirm also carries `role="dialog" aria-modal="true"`. Good. No action beyond adding `aria-labelledby` to dialog-content for screen-reader labelling (nice-to-have).

### Low (cosmetic / nice-to-have)
L1. `app.css` has both `prefers-reduced-motion` blocks (one in each vocab section) — harmless duplicate, consolidate.
L2. `static/robots.txt` + `favicon.svg` present (from July). SEO baseline OK. Sitemap not observed — verify `sitemap.xml` covers the SIS/communications/finance routes if SEO matters.
L3. `credential-security.test.ts` + `mpesa-callback.test.ts` cover the money path's idempotency/security — good. No live-DB integration tests (acceptable for money-path; migration-string + unit pattern holds).
