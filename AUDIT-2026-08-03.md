## 1 · Executive summary

This is a **healthy, coherently-architected, late-beta codebase**. Two financial domains (school fees / bank-KCB vs remedial / M-Pesa paybill) are cleanly separated at the data layer, tenant isolation is enforced in server loaders with a **real, passing 41-test tenant-isolation suite** plus a dedicated `tenant-isolation.test.ts`, and the `paginatedQuery`/`withTenant` wrappers from `_platform` mean the "naive scanner false-positive" class documented in the skill library does not apply here. Money paths (STK, callback, reconcile RPC, per-domain payroll, receipts) are in dedicated, single-purpose modules; contribution to them is well-guarded by role layouts + module gating.

The codebase has earned its 0-error gates honestly — there are **no `@ts-nocheck` files**, no `TODO/FIXME`, zero template contamination, no brand leakage, and every dependency except `tailwind-variants` is used.

The real risks are narrow and fixable:

1. **Impersonation middleware fetches the session row without an expiry/revocation filter, and includes a dead-code PK-vs-user comparison** (`middleware.ts:99-112`). Functionally the fallthrough to `admin_user_id` saves it, but the row-selection is wrong-by-omission (stale/expired rows are in the result set).
2. **Delete confirmation is inconsistent** — credentials + notifications + scheduling confirm; students, teachers, parents, users, subjects, income, expenses delete with a bare POST form and no `confirm()`. In a school app, deleting a student/teacher silently is a High.
3. **Infra ambiguity**: Vercel adapter *and* a Dockerfile, no CI workflow file, playwright + test-results + `__pycache__` + `graphify*` artifacts at repo root.
4. **47 lint warnings are a uniform class** (`no-unused-vars` incl. unused `notFound` import inside `mpesa-callback`) — zero-risk to fix, high signal.

Everything else is solid: RLS policies exist but are *aspirational defense-in-depth* behind the documented service-role pattern — consistent with the user's architecture notes, and now actually accurate after the `20260720000002_enable_rls_policies` migration enabled them.
